# M1 — Requirements, Architecture & Repository Foundation

## Objective

Establish a coherent, reviewable foundation for StreamForge before application implementation: define the IoT telemetry MVP, architecture and reliability boundaries, initial event contract, engineering practices, accepted decisions, risks, and repository conventions.

## Approved Scope

M1 is limited to:

- project overview and documentation navigation;
- functional and non-functional requirements;
- target architecture and transaction boundaries;
- initial `telemetry.reading` V1 contract;
- ADR-01 through ADR-10;
- development environment record and workflow;
- future testing strategy;
- known-issue and risk register;
- root `.gitignore` and `.editorconfig`;
- this milestone record.

Application code, dependencies, generated source projects, empty source directories, runtime infrastructure, installations, tests of unimplemented behavior, Git writes, and deployment are outside M1.

## Acceptance Criteria

- Every expected file exists and contains substantive content.
- README distinguishes planned architecture from implemented functionality.
- Requirements define MVP scope, exclusions, journeys, reliability, security, and acceptance principles.
- Architecture identifies logical components versus deployment units, boundaries, data flow, transactions, outbox behavior, and failure scenarios.
- The event contract documents required V1 fields, lifecycle times, duplicate/conflict behavior, and event-time versus processing-time semantics.
- Each accepted decision has one ADR with context, decision, rationale, alternatives, consequences/trade-offs, and risks/deferred details.
- Development records the supplied environment audit and makes no unsupported readiness claim.
- Testing distinguishes future requirements from checks actually executed.
- Risks and unresolved decisions remain visible.
- Relative documentation links resolve.
- No architecture contradiction, invented benchmark/test/deployment claim, or exactly-once claim is present.
- No package installation, application implementation, deployment, secret creation, or Git write occurs.
- Independent Final Check and user approval are recorded before M1 is marked complete.

## Known Limitations

- No Java 21 ARM64 JDK or Docker runtime is currently available according to the supplied audit.
- No Maven build, Maven Wrapper, source code, dependency, database, Kafka broker, frontend, or infrastructure configuration exists.
- No runtime tests have executed or are applicable to this documentation-only milestone.
- Contract validation details, API schemas, persistence schema, Kafka topology, retries, replay, read models, security design, observability tooling, SLOs, and deployment details remain open.
- Single-node Kafka is only a future local-development plan and will provide no broker high availability.
- EC2 plus Docker Compose is only a candidate pending M9 evaluation and explicit deployment approval.
- M2 — Java Backend Foundation has not started.
