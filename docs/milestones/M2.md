# M2 — Java Backend Foundation

## Objective

Create a working Java 21 / Spring Boot API foundation with Maven Wrapper, PostgreSQL via Docker Compose, Flyway migrations, structured error handling, Testcontainers coverage, and baseline GitHub Actions CI.

## Approved Scope

- Root Maven aggregator and `backend/api` module
- Maven Wrapper 3.3.4 using Maven 3.10.0
- Spring Boot 4.1.1 API with Actuator health
- JDBC + Flyway against PostgreSQL 17.11
- RFC 9457 Problem Details for validation, malformed JSON, and unexpected errors
- Local Compose PostgreSQL bound to loopback only
- JUnit + Testcontainers integration tests
- Minimal GitHub Actions Maven verify workflow
- Development and testing documentation updates

Telemetry ingestion, outbox, Kafka, Worker, frontend, authorization product endpoints, and AWS resources are outside M2.

## Acceptance Criteria

- `./mvnw -B -ntp verify` succeeds on Java 21
- Application context starts against real PostgreSQL
- Flyway applies the M2 platform migration
- Actuator `/actuator/health` returns UP without component details
- Validation and malformed JSON produce RFC 9457 responses without stack traces or credentials
- Compose publishes PostgreSQL only on `127.0.0.1`
- No unauthenticated mutating business endpoints exist
- No secrets are committed
- Independent Final Check and user acceptance remain required

## Known Limitations

- Telemetry and device APIs were outside the accepted M2 scope. They are implemented in M3, which is pending acceptance.
- Security identity model remains open (R-13)
- Kafka and Worker are deferred
- The owner reported that remote GitHub Actions passed. This agent did not independently inspect that run.
- Local Compose credentials are development placeholders, not production secrets
- V1 is immutable on databases that already applied it. The duplicate `CREATE SCHEMA` warning remains because editing the script would change checksum `595439424`
- `schema_info` stays until a later reviewed migration. M2 does not drop it
- Testcontainers 2.0.5 accepts the Ryuk digest in `testcontainers.properties` and logs that image substitution is deprecated. Re-check that property before a Testcontainers upgrade

## Migration integrity

V1 was left unchanged after the corrective review. Fresh Testcontainers databases apply that same file. The existing Compose volume is validated in place and is not repaired, recreated, or rewritten.
