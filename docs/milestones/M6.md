# M6 — Storage, Analytics & Historical Processing

## Objective

Answer device-scoped telemetry questions from accepted PostgreSQL rows, and provide a repeatable rebuild of derived hourly statistics. Do not claim that a past window is final, and do not claim exactly-once delivery.

## What M6 implements

- `GET /api/v1/analytics/devices/{deviceId}/summary`
- `GET /api/v1/analytics/devices/{deviceId}/series`
- `GET /api/v1/devices/{deviceId}/readings`
- Device-admin authentication on all three routes
- Aggregates from `streamforge.telemetry_events`, including rows whose outbox is pending or failed
- UTC event-time windows, half-open `[from, to)`
- Hour and day buckets that do not follow the database session time zone
- Keyset pagination on `(occurred_at, event_id)` descending
- Flyway `V5__analytics_hour_stats.sql`
- An explicit rebuild command that is off unless `STREAMFORGE_ANALYTICS_REBUILD_ENABLED=true`

The API does not read `device_hour_stats`. A newly accepted late event is visible on the next query without a rebuild. `processed_events` is not a filter and not a skip list.

## Analytics semantics

`occurred_at` is the event time. `received_at` is ingestion time. `processed_at` is the Worker receipt time. Summary and series filter on `occurred_at`.

A bucket that overlaps only part of the requested range counts only readings inside the range. `bucketStart` and `bucketEnd` still name the full UTC hour or UTC day. Hours and days with no readings are omitted. Empty numeric aggregates are null, not zero.

Averages are `ROUND(AVG(numeric), 3)`. PostgreSQL rounds half away from zero. `21.705` is a valid scale-3 temperature. `21.7051` is rejected by the existing validator.

`publicationBacklog` and `processingBacklog` count the device's full accepted history, not the requested window. Publication backlog is outbox rows still `pending`. Processing backlog is accepted rows with no receipt. The outbox join is one row per event.

`history.latestReceivedAt` is `MAX(received_at)` for the device. It can belong to a different reading than `history.latestOccurredAt`.

`windowOpen` is true when `to` is after the server clock. A window in the past can still change when a later request carries an `occurred_at` inside it. There is no finalized flag.

Separate reading pages do not share a database snapshot. A static dataset pages without duplicates or gaps. A concurrent insert can change a later page.

## Historical rebuild

Normal API startup does not rebuild. The command exits after one invocation and does not bind an HTTP port:

```bash
export STREAMFORGE_ANALYTICS_REBUILD_ENABLED=true
export STREAMFORGE_ANALYTICS_REBUILD_FROM=2026-06-15T10:00:00Z
export STREAMFORGE_ANALYTICS_REBUILD_TO=2026-06-16T02:00:00Z
export STREAMFORGE_ANALYTICS_REBUILD_DEVICE_ID=sensor-042
java -jar backend/api/target/streamforge-api-0.1.0-SNAPSHOT.jar
```

Omit the device id to rebuild every device in those days. Resume with `STREAMFORGE_ANALYTICS_REBUILD_RUN_ID` and do not also set a range.

The requested interval selects every UTC day it intersects. Each selected day is deleted and recomputed in full, for that device scope only. An exact UTC midnight `to` does not include the following day. One advisory lock covers the invocation. Each day is its own transaction: delete, insert, and checkpoint commit together. `next_chunk_start` is the first UTC midnight not yet committed. `completed` is set only when that checkpoint reaches `effective_to` in the same update. A thrown chunk rolls that day back and marks the run `failed` without moving the checkpoint. Resume continues at `next_chunk_start`. A second command that cannot take the lock exits without writing. A stale `running` row is resumed by its run id after the lock is free; it does not block a different new run.

`max_source_received_at` is the greatest `received_at` in the rows that formed the bucket. It is not a consumer watermark and does not mean the hour is complete. Rebuilding the day replaces the bucket. Until then the derived row can lag the raw table.

Exit codes: `0` completed, `2` lock held, `1` rejected or failed.

## Limits

| Route | Maximum span | Notes |
| --- | --- | --- |
| Summary | 366 days | `from` and `to` required |
| Series `hour` | 31 days | |
| Series `day` | 366 days | |
| Readings | 7 days | `limit` default 100, maximum 500 |

Unknown devices return 404. A known device with no rows returns 200. The ingestion key returns 403. A missing key returns 401.
